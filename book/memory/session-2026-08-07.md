# Session — the findings lane, 2026-08-07

*What happened is in [[Handoff — where things stand]]; this page does not repeat it. This is the
shape of the session, what it got wrong, and what it left standing — the part that has nowhere else
to live. Durable lessons went to [[learned]]; the one thing needing a ruling went to
[[open-questions]].*

## The shape

Two lanes ran in parallel off one fork point. The **rig lane** built the agent rig, the viewer, the
fixtures and wired eight of the ten named agents. This lane — the **findings lane** — closed
adversarial findings and ran the strike waves. They were merged at the end; they had touched **no
source file in common**, and the only overlapping file in the whole merge was `docs/HANDOFF.md`.

That is a good outcome and a bad process. The LANES table in the handoff, which exists precisely to
prevent two hands colliding, was **empty the entire time both lanes were running.** Nothing was lost,
but nothing was protecting it either.

## Closed

Six findings, none speculative, each against a named file:

- the vault would replay an **advancing** batch onto a document that moved under it
- an agent-completed step carried **no `actor`** — the machine's work read as the operator's
- the fleet counted **swept steps as proposals**, summoning the human to an empty Ledger
- an unreachable `overridden` Approve branch
- three strike waves: the orphaned 3D realm, the retired 3D war table, the multi-person-firm model

The last went to the orphan branch `archive/multi-person-firm` rather than to nothing, because a
multi-person firm is a real shape another product might want whole. The scenery got no branch — its
design survives in the writs and it is not waiting to come back.

## What this session got wrong

Four times, and the pattern is one pattern:

1. **"Most of `src/realm/` is dead."** Half of it is live — `WarTableView` and `FlatMapView` both
   import from it. From a note, not from the tree.
2. **"The `overridden` Approve is a dead button."** It was unreachable code, not a live button.
   `readFlow` counts `overridden` among the acted kinds, so the ball always moved past it.
3. **"The rig branch touches eight of my files."** It touched one. See [[learned]] — the diff was
   taken against the wrong base and showed my own work back to me.
4. **`git add -A` on a fresh orphan branch** staged `node_modules` and `dist`.

Every one was caught by looking at the bytes, and every one had been *written down confidently first*.
This is the same failure `learned`'s NUL-byte entry already describes, arriving four more times in a
single day. The repository's own instruction — **verify claims against the bytes** — is not a
posture. It is the whole job.

## Left standing

- **Nothing reads the `actor` stamp yet.** `readEscape` still cannot separate a swept step from a
  worked one, which was half the reason the stamp mattered. The field exists for that fold to be
  written against; the fold is not written.
- **The settlement gate has never been observed refusing in the running app** — only in unit tests.
  A guard built ahead of its door, which is the right order, but a green suite is not evidence it
  has bitten.
- **Finding 4, the calendar window**, is still never compared to a date — and fixing it would
  *silently arm unattended owner disbursement*, because that clause is currently the only thing
  barring it. It needs a second gate designed alongside it, not a patch.
