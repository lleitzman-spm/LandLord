# Brief: word-core (speech → orders)

**Your files:** `src/word/index.ts`, `model.ts`, `digest.ts`, `prompts.ts`, `interpret.ts`, `offline.ts`, `test/word-core.test.ts`, `tools/word-harness.ts`.
**Read:** `src/word/api.ts` (you implement `createWord`, `WordAPI`, `Exchange`, `ModelClient`), the placeholders `src/word/audience.ts` and `mic.ts` (another agent is writing them; you call `openAudienceSession(id, deps, () => model, notify)` and `createMic()`), `src/sim/types.ts` (Action, ActionResult, StandingOrder, Condition, Policies, Oath, DecisionType, DECISION_OPTIONS), `src/data/schema.ts` (TemperamentDef: `voice`, `bias`, `acks`, `grumbles`), `src/data/index.ts`, `docs/BIBLE.md` "Ruling by word", `src/dev/fixture.ts`.

The ruler types or says something to a delegate, a household, a building, or the room. You turn it into validated Actions and a read-back in the listener's voice.

**Transports** (`model.ts`): `detectModel(): Promise<ModelClient>`.
1. `server`: `GET /api/court` (same origin, 2.5 s timeout) answering `{ ok: true, model: true, gated: boolean }` means `POST /api/word` with JSON `{ system, messages, maxTokens, tier, key? }` returns `{ text }` (errors: `{ error, code }` with HTTP 4xx/5xx; 401 means the court key is wrong: surface that so the UI can ask for it; read the key from `localStorage['ll.courtKey']` in a try/catch).
2. `claude`: if `window.claude?.use` exists, `await window.claude.use('sample')`; when non-null, call `sample(input, { modelTier: tier === 'default' ? 'default' : 'quick', cache: false, signal })` where `input` is the turn list with the system text as a leading user turn (there is no system role); map its rejection codes (`not_granted`, `rate_limited`...) to a graceful offline fallback for that call; never retry in a loop.
3. `none`.
`ready` resolves when detection ends. Detection never throws and never blocks the game.

**The digest** (`digest.ts`): a compact, token-thrifty text snapshot the model can act on: date, season, rank, coffers, policies; delegates (role, first name, temperament, busy or free); buildings (id, name, type, condition, asking rent, who lives there, flags); households (id, name, species, trade, tags, revealed traits only, rent, arrears, days late, happiness band, months housed); open incidents (id, title, where, outcomes by id and label); standing orders (id, to, gist); open oaths. Scope it to what the target makes relevant when the realm is large (cap about 6,000 characters).

**The prompt** (`prompts.ts`) asks for **strict JSON only**:
`{ "speaker": role or "herald", "reply": string, "mood": Mood, "understood": boolean, "actions": Action[], "confirm": boolean }`
with the Action vocabulary spelled out as a schema the model can follow (only the kinds a spoken order can mean: order_job, resolve_incident, set_rent, set_listed, collect_all, add_order, revoke_order, set_policy, swear_oath, gift, hold_feast, hire, dismiss_staff, set_wage, place_road is NOT allowed, place_building is NOT allowed: "buildings are placed by hand"), the rules for standing orders (how to express "never evict a widow in winter" as decision/when/rule/option; the CondField list; `text` must be the ruler's verbatim words and `gist` the delegate's short read-back), and for oaths (only when the ruler actually promises something; choose the kind; due day from the words or a sensible default). The reply is the listener **reading back what they understood, in character**: give the model the temperament's `voice`, `blurb` and `quirk`, the STYLE.md rules that matter (dry, short, no em dashes, no modern words, under 200 characters), and tell it that where the order leaves latitude the delegate fills it **according to temperament** and says so in the read-back (the Iron bailiff hears "deal with the late payers" as notices; the Soft one as payment plans). `confirm: true` for anything weighty: standing orders, evictions and notices, dismissals, spending over a tenth of the coffers, broken-oath risks. Include two or three tiny worked examples. If the words are not an order at all (a greeting, a question, an insult), `actions: []` and a characterful reply; questions about the realm are answered from the digest.

**Interpreting** (`interpret.ts`): parse tolerantly (strip code fences, find the outer braces), validate every action's shape against the types (drop unknown kinds, coerce numbers, check ids exist, check `option` is valid for `decision`), then: if `confirm`, hold them as `pending` (`needs_confirm`); else dispatch each through `deps.dispatch` and collect results. A refusal turns the status to `refused` and appends the sim's `reason` to the reply in the speaker's voice. `confirm()` dispatches the pending ones. Count `stats.wordsSpoken` via `set_flag`? No: leave stats alone. Notify listeners on every change. Keep the last 30 exchanges.

**Offline** (`offline.ts`): a real, useful parser for when there is no model: verbs and patterns for the common orders ("fix/mend/repair X", "collect the rents", "evict X", "serve notice on X", "raise/lower/set the rent at X to/by N", "list/unlist X", "show X the hovel", "hire the mason", "hold a feast", "give X 10 crowns", "N days' grace", "late fee N percent", "no pets / pets allowed / pet rent", "always/never …" → a best-effort standing order for the patterns it recognises), fuzzy matching of building and household names, and read-backs drawn from the temperament's `acks` / `grumbles` with the order restated. When it cannot parse: `unclear`, with a line that hints at what it does understand.

**Harness and tests.** `tools/word-harness.ts <rank> "<utterance>" [role]` prints the exact system and user text you would send for the fixture state, so that prompts can be tried against real models by other agents. `test/word-core.test.ts`: the validator against a dozen hand-written model replies (good, malformed, hostile: unknown ids, a `place_building`, a 10,000 crown gift), the offline parser across forty phrasings, and the confirm flow, using a scripted `ModelClient` and `fakeSim`.
